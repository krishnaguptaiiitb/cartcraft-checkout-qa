## 2. Validate locally before publishing

```powershell
npm run build
npm run test:e2e
npm run test:e2e:report
```

Keep the existing `package-lock.json` that was generated by installing the application and Playwright. **Commit the lockfile**. CI uses `npm ci` to install exactly the locked versions.

## 3. Initialize Git and make a clean commit

```powershell
git status
```

If Git says *not a git repository*, execute:

```powershell
git init
git branch -M main
```

Then:

```powershell
git add .
git status
git commit -m "feat: add checkout, 16 browser tests, QA evidence and CI"
```

Verify `node_modules/`, `dist/`, and `playwright-report/` are not staged; the supplied `.gitignore` excludes these while including curated evidence under `evidence/`.

## 4. Publish to GitHub (after creating an empty repository)

In your browser, create an **empty** GitHub repository named `cartcraft-checkout-qa` (no generated README/license/gitignore). Copy your actual remote HTTPS URL. Then run, replacing the placeholder with that URL:

```powershell
git remote add origin https://github.com/YOUR-USERNAME/cartcraft-checkout-qa.git
git push -u origin main
```

If `origin` already exists, inspect `git remote -v` and set its URL with `git remote set-url origin <your-real-url>` instead of adding a second remote. Use your normal GitHub authentication method; do not paste a personal access token into source files or chat.

## 5. Verify GitHub Actions — do not claim success before it runs

Open the repository's **Actions** tab and open **CartCraft Quality Gate**. Check the run's green status and inspect individual build / Playwright steps. The workflow runs on push, pull request, or a manual **Run workflow** action. When successful, download the `cartcraft-playwright-html` artifact for the full HTML report, or inspect `cartcraft-playwright-raw-results` for failure traces/JUnit. If GitHub restricts workflows in a new repository, enable Actions in repository settings.

The CI workflow follows Playwright's published GitHub Actions approach, with Chromium-only installation and a single test worker without retries for clear results.

## Troubleshooting

- `npm ci` says no lockfile: `npm install`, then commit the generated `package-lock.json`.
- Browser executable missing: `npx playwright install chromium` (Windows) / `npx playwright install --with-deps chromium` (CI Linux).
- Port 5173 in use: stop the other Vite process. CI's Playwright server deliberately uses `--strictPort`.
- Tests fail on Linux: view GitHub workflow logs and download its artifact before changing tests. Don't weaken assertions merely to make CI green.
- HTML report missing: ensure `npm run test:e2e` completed and open `npm run test:e2e:report`.
